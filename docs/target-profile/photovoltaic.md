# Photovoltaic source coverage for the Matter binding

This is a partial source-side inventory for [binding issue #12](https://github.com/Project-Helianthus/helianthus-matter-binding/issues/12), advancing [parent #8](https://github.com/Project-Helianthus/helianthus-matter-binding/issues/8). It does not complete the locked Matter target inventory, release M42/M43, or close the parent. Nothing is stable before Helianthus 1.0. This document records current source behavior and proposed reconciliation questions; it creates no native facts, accepted mapping, runtime endpoint, composition profile, or qualification.

Protocol facts remain owned by the public native documentation; SemReg owns the neutral definitions, the Gateway owns current publication, the public semantic documentation repository owns Matter target mappings, and this repository owns the SDK boundary and admission. This inventory does not amend those contracts. Application lifecycle belongs outside protocol/type trees. No authentication, principal, permission, or credential check is introduced; authentication/authorization remain 0.11 subjects, with no new authorization gate before 0.9.

## Evidence vocabulary and the locked boundary

**Proven** means directly present in the cited source contract or implementation, not executed hardware evidence. **Hypothesis** marks a proposed correspondence still requiring evidence. **Unknown** marks missing evidence, including target schema not supplied for inspection. These grades are independent of native qualification, semantic representability, target-model verification, and production admission.

The [lock][lock] explicitly records data-model version `1.7`, Electrical Sensor `0x0510` revision 2, Power Topology `0x009C` revision 2, Electrical Power Measurement (EPM) `0x0090` revision 3, and optional `ActiveCurrent` `0x0005`. These are **lock metadata only**, not an inspected full schema. No other numeric target identifiers or revisions are asserted here. The lock references the semantic mapping path `api/v1/targets/matter-1.7-ballot-0.9-v1.json`; its PV coverage was not inspected. The [baseline][baseline] records only `evse.ac.current` as the accepted mapping, not a PV mapping.

Every matrix row below inherits **A0: Matter production admission denied**: the lock's `accepted_runtime_composition_profile_sha256` is null, and [production readiness][readiness] denies every allocation request before trusting caller composition or build evidence. A successful source publication or SDK sample fixture cannot change A0. There is no currently composed Helianthus PV hardware support established by these sources; physical qualification, conformance, interoperability, certification, production fabric operation and deployment remain unproven.

Every row also inherits **C0: composition evidence missing**. The baseline/runtime require evidenced Descriptor and Power Topology composition and EPM `PowerMode` (non-unknown), positive `NumberOfMeasurementTypes`, nonempty fixed `Accuracy` matching the count, and an evidenced nullable `ActivePower` fact. These are recorded baseline/runtime requirements, not independently verified schema conclusions. A nullable fact requires evidence; absence is not fabricated zero. The full locked corpus must reconcile these requirements, device composition, measurement scope, phase topology, units/scaling/ranges, optionality, feature conditions and accepted PV mapping. Native amperes or watts alone supply none of the missing composition authority.

**T0** in a target cell means device type/cluster/feature/attribute correspondence is **Unknown**; there is no inferred negative target-support claim. **TC** means the optional `ActiveCurrent` lock metadata is a candidate search lead only; PV suitability, feature requirements, phase representation, scale and numeric encoding remain **Unknown**. **TP** means EPM active-power correspondence is a candidate search lead from the baseline only; attribute ID, features, units and semantic direction remain **Unknown**. Neither TC nor TP is an accepted target mapping. All rows explicitly carry A0 and C0 so source coverage cannot be mistaken for admission.

## Source and qualification boundary

The [SunSpec native core][core] defines bounded read-only decoding, exact decoder keys, sentinel handling, opaque retention and field-by-field equivalence. Integer three-phase and float three-phase representations are not interchangeable merely because their model labels agree. The [Fronius qualification contract][fronius] enumerates fourteen candidate facts from the uniquely selected three-phase inverter occurrence. An offline replay match retains raw words, occurrence order, source spans and logical-view provenance; it remains `live_qualified=false`, `automatic_runtime_admission=false`, `write_authority=false`.

The [Fronius selector][flavor] evaluates generic monitoring separately from the exact vendor flavor. Generic capability may survive a manufacturer/firmware/chain mismatch that defeats the flavor. Exact vendor matching depends on the source's identity, firmware and ordered chain, not the family name; no individual model or hardware identifier is reproduced here. The [Gateway publication core][publication] checks the admitted generic monitoring capability, rather than requiring a Fronius flavor match. Its qualified/promoted semantic labels describe that publication path; they do not convert offline evidence into hardware qualification.

## Sign, unit, scope and retention review

Current source behavior preserves inverter signed active power without multiplying by a presumed generation/export sign. The pack permits signed aggregate and phase active power, but that numeric range does not define grid import/export orientation. Phase current is nonnegative in the pack; negative native values fail validation rather than becoming a direction flag. A generator family label does not establish a point of common coupling, meter role, wiring topology, bidirectional measurement or site balance. Grid import/export needs separately owned native measurement location and sign evidence plus an accepted semantic and target contract.

Lifetime SunSpec Wh becomes decimal kWh by reducing the decimal exponent by three; canonical zero stays zero. Energy retains the explicit continuity loss, so no interval rate, delta, reset or rollover interpretation is invented. Growatt synthetic energy is already scaled in kWh; it must not reuse the Wh conversion. Power remains W, current A, voltage V, frequency Hz and temperature Celsius in the current SunSpec publication. Units do not establish direction.

The [publication core][publication] retains evidence references in deterministic candidates and projection dispositions. Rejected lifecycle drafts leave current epoch/handles/public views untouched; stale or unavailable facts have no current presentation selection, while evaluation remains visible ([lifecycle][lifecycle], [selection][selection]). This inventory requires preserving native evidence and partial last-known-good state without presenting retained data as fresh. The supplied core is not sufficient to prove all MCP/GraphQL routes: consumer parity and eBUS MCP compatibility remain unchanged requirements, unverified here, with no new route or envelope proposed.
