# Storage source coverage for the Matter target inventory

This binding-local inventory advances [issue #9](https://github.com/Project-Helianthus/helianthus-matter-binding/issues/9) as a partial source-side slice of [parent #8](https://github.com/Project-Helianthus/helianthus-matter-binding/issues/8). It cannot close the parent or release M42/M43. Full locked-corpus target verification remains open. Nothing here is stable before Helianthus 1.0.

This document inventories existing public native evidence and candidate semantic correspondence. It creates no native fact, adapter, universal target mapping, runtime endpoint, profile admission, acquisition or command. Binding coverage belongs here; protocol-neutral contracts remain with SemReg, native contracts with their driver documentation, and accepted Matter mappings with the public semantic documentation owner. No authentication, principal or permission interface is introduced.

## Evidence and target boundary

Evidence labels are independent of qualification: **Proven** means a cited source explicitly defines the stated bounded behavior; **Hypothesis** means a proposed correspondence awaiting evidence; **Unknown** means required source or target evidence was not inspected. None means hardware qualification, interoperability or certification.

The [reviewed lock][lock] explicitly records data-model version **1.7** and these **lock metadata**, not an inspected full schema:

| Lock key | Explicit metadata |
| --- | --- |
| `target.device_type` | Electrical Sensor, `0x0510`, revision 2 |
| `target.power_topology_cluster` | Power Topology, `0x009C`, revision 2 |
| `target.electrical_power_measurement_cluster` | Electrical Power Measurement, `0x0090`, revision 3 |
| `target.active_current_attribute` | ActiveCurrent, `0x0005`, optional |

These metadata do not identify a battery target, battery feature set, SOC attribute, energy attribute, voltage attribute or status attribute. Their support is **Unknown**, not disproven. The [baseline][baseline] describes only `evse.ac.current` as the accepted mapping; that is not a battery mapping. A battery must not inherit Electrical Sensor admission from the EVSE slice. The actual mapping payload and complete locked SDK schema were not supplied.

The following codes apply to **every matrix row**, including unavailable rows:

- **U**: target device type / cluster / feature / attribute correspondence is **Unknown**. No numeric target claim beyond the lock metadata above. For pack current, ActiveCurrent is only an investigation lead; its optional lock entry proves no battery applicability, DC feature, sign convention or unit conversion.
- **G**: mandatory composition evidence is missing: a battery-appropriate device composition, exact feature and attribute rules, nullability, units, accuracy, topology and identity continuity. For the currently described Electrical Sensor route, the baseline/runtime additionally require evidenced Descriptor, Power Topology, Electrical Power Measurement, non-unknown PowerMode, positive NumberOfMeasurementTypes, nonempty matching Accuracy and nullable ActivePower. This is a current local readiness contract, not independent verification of SDK mandates.
- **A**: production admission **denied**. The lock has no accepted runtime composition-profile digest; [the evaluator][readiness] rejects before trusting caller metadata or build results. Even complete source facts or a passing sample build do not change this.

## Current behavior versus proposed correspondence

Current Growatt code decodes a complete bounded base observation, retains native evidence, and separately evaluates the opt-in diagnostic. It does not acquire data, merge repeated packs, or expose these proposed SemReg/Matter relationships. A failed diagnostic yields no partial diagnostic and does not erase qualified base telemetry. A future lifecycle consumer must reject missing, duplicate, changing or contradictory repeated identity without renumbering survivors or discarding unaffected last-known-good state. The native document requires MCP projections to retain exact native slices; this inventory adds no interface and claims no implemented MCP/GraphQL adapter or parity result. Any future adapter must preserve native evidence and equivalent facts and withholding across both surfaces.

There is a source discrepancy requiring reconciliation before the operating-state candidate can be accepted: the native document says other state encodings reject, but the typed decoder checks the high byte and then switches on `bits & 0x03`. Extra low-byte bits can therefore be masked. The typed base keeps the balance word opaque; the separately qualified diagnostic interprets that word. Neither distinction justifies broadening base telemetry or changing unowned code here.
